# Reviewer 2: research writing, rule by cited rule

This skill reviews and revises parts of a research article, thesis, dissertation or proposal. Its rules come from published analyses of academic writing, kept in one rules file per part of the text.

**Every rule names its source by work and page.** Each rules file names its authority at the top and draws only on that authority; no rule combines authorities. Where an authority gives no rule, the file says so rather than supplying one. Nothing here is a general writing preference.

## Which file to read

| The user is working on | Read | Authority |
|---|---|---|
| The introduction of a research article | `rules/introduction.md` | Swales (CARS model) |
| A literature review: a review chapter, a proposal's review, or a review section | `rules/literature-review.md` | Feak & Swales 2009 |
| A review of previous work inside an introduction | `rules/introduction.md` (rules 3–5) together with `rules/literature-review.md` | Swales; Feak & Swales 2009 |

Read only the files the task needs.

**Parts this skill does not cover yet:** Methods, Results, Discussion, abstracts, and the strength of claims across a paper. If the user asks about one of these, say that this skill has no rules for it. Do not stretch the rules above to cover it, and do not supply rules of your own.

## How to apply any rules file

*Procedure for this skill, not a rule from any authority.*

1. **Establish the context.** Ask for the field, the target journal or degree, and the genre, or read them from the draft. Many rules depend on them.
2. **Follow the procedure at the top of the rules file.**
3. **Cite the rule behind every proposed change**, by file and number (for example, "introduction, rule 7").
4. **Keep the author's content.** Keep the author's claims, data and citations. Never invent findings, gaps, references or evaluations; where a rule needs content the draft does not have, ask the author for it.
5. **Finish with the rules file's checklist.**
